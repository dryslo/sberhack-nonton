## Как всё связано

```
data/*.csv
  core.load_data()               всё позже 26.07.2026 отрезается сразу
  features.Panel                 матрицы пара x неделя, признаки на неделю отсчёта T
    classifier.py                вероятность продажи на неделе T+h
    regressor.py                 сколько продадут, если продажа будет
    pipeline.decide              вероятность выше порога -> целое количество, иначе 0

бэктест   core.backtest: make_forecast(..., "pipeline") на трёх фолдах с отсечкой в прошлом
финал     final.PARAMS -> Forecaster.fit на всей истории (notebooks/06_final, Kaggle) -> model/
сабмит    Forecaster.load(model/).predict -> submission/submission.csv
сервис    app/ -> тот же Forecaster -> прогноз по присланным файлам
```

Код прогноза общий для бэктеста, сабмита и сервиса. Поэтому то, что проверяли, и то, что отдаёт сервис, не расходятся: прогноз контейнера по последним 180 дням совпадает с сабмитом байт в байт.

## Где что менять

| Что нужно | Где |
|---|---|
| новый признак | `src/features.py`: посчитать в `Panel.features`, добавить в `GROUPS`, потом в `FEATURES` нужной модели; проверить через `feature_ablation` |
| другой набор признаков у модели | `FEATURES` в `src/classifier.py` или `src/regressor.py`; на один эксперимент можно передать `features=[...]` |
| настройки модели | `PARAMS` и `ORIGIN_STEP` там же; в ноутбуке только на текущий запуск |
| порог и правило решения | параметры метода `pipeline` в `src/pipeline.py`, итог в `src/final.py` |
| свой метод прогноза | функция с `@register("имя")` в ноутбуке или в `src/` |
| проверить идею | ноутбук в `notebooks/05_experiments/` по образцу, `make push NB=<имя>` |
| новая финальная модель | `src/final.py`, `make run NB=06_final`, скопировать `model/` и `submission.csv` из `outputs/kaggle/06_final/`, потом `make test`, `make up`, `make check-container` |
| поведение API | `app/routes/`, схемы ответов в `app/schemas.py` |
| другая модель в сервисе | своя реализация `ForecastModel` в `app/predictor.py` или папка модели с `config.json` (поле `kind`) и `MODEL_DIR` |

## Как шла работа

1. Меняли одну вещь за раз: признак, настройку или порог.
2. Смотрели метрики своей ступени в `03_classifier` или `04_regressor`, а идею целиком проверяли отдельным ноутбуком в `notebooks/05_experiments/`: база считается в том же запуске, на Kaggle это ~15 минут, и несколько идей можно гонять параллельно.
3. Брали идею, только если она не хуже базы на обоих сезонных фолдах, а на `recent` хуже не больше чем на 0.005. Все проверки с числами и причинами записаны в `results/ideas.csv`.
4. Лучший вариант переносили в `src/final.py`, обучали финал на Kaggle и проверяли контейнер.
