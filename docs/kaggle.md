# kaggle/: запуск ноутбуков на Kaggle

Локально памяти около 8 ГБ и нет GPU, поэтому тяжёлые ноутбуки (03, 04, 05_*, 06_final) выполнялись на Kaggle. `kaggle/run.py` делает это одной командой из папки проекта.

| Команда | Что делает |
|---|---|
| `make check` | есть ли токен Kaggle и загружены ли данные |
| `make data` | загрузить `data/*.csv` приватным датасетом (повторный вызов создаёт новую версию) |
| `make run NB=03` | выполнить ноутбук на GPU, дождаться и забрать выводы |
| `make push NB=03` | запустить без ожидания, потом `make status NB=03` и `make pull NB=03` |

`NB` - короткий номер (01-05) или имя ноутбука из `notebooks/` и `notebooks/05_experiments/` без `.ipynb`. У каждого ноутбука свой запуск на Kaggle, поэтому несколько можно гонять параллельно.

## Как это работает

```
локально   src/*.py и ноутбук без выводов упаковываются в runner.py, kaggle kernels push
Kaggle     runner.py раскладывает src/ и notebooks/ как в проекте, данные берёт из приватного датасета,
           выполняет ноутбук по ячейкам и сохраняет его после каждой
локально   make pull скачивает выполненный ноутбук, CSV и лог в outputs/kaggle/<ноутбук>/
           и переносит выводы в notebooks/<ноутбук>.ipynb
```

- На Kaggle уходит один скрипт: модули `src/` и ноутбук лежат внутри него в base64. Так запускается ровно текущий код, а не то, что когда-то лежало в датасете.
- Ноутбук сохраняется после каждой ячейки, чтобы при обрыве сессии сделанное не пропало.
- На Kaggle модули сами ставят полные настройки (`ON_KAGGLE` в `src/core.py`), журнал и сабмит пишутся в `/kaggle/working`.
- `pull` переносит выводы только в ячейки, текст которых не менялся с момента запуска, поэтому локальные правки не затираются.
- GPU: Tesla T4, P100 Kaggle больше не выдаёт. Токен лежит в `~/.kaggle/kaggle.json`.
