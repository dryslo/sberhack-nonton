# notebooks/: ноутбуки

Вся логика лежит в `src/`, а ноутбуки только запускают её и показывают таблицы и графики. Первая ячейка с кодом добавляет `src/` в путь (`../src`, у экспериментов ещё `../../src`). Тяжёлые ноутбуки (03, 04, 05_*, 06) выполнялись на Kaggle GPU через `make run` или `make push` (см. [kaggle.md](kaggle.md)), выводы в них оттуда.

| | локально | на Kaggle |
|---|---|---|
| настройки моделей | облегчённые: каждая 4-я неделя отсчёта, 300-500 деревьев (WSL, ~8 ГБ памяти) | полные: все недели отсчёта, 400 деревьев, GPU T4 |
| как запустить | Run All | `make run NB=03` |
| журнал и сабмит | `outputs/` | `outputs/kaggle/<ноутбук>/` |

## solution.ipynb

Обзор решения: задача и метрика, данные, схема модели, как проверяли, путь от наивного прогноза до финала, что сработало и что нет. Ничего не обучает: числа берутся из `results/` и `model/config.json`, ноутбук пересчитывается за секунды. `make solution-html` делает из него страницу `/solution` в сервисе.

## 01_start.ipynb

Начало работы: бейзлайны (наивный, нули, среднее и медиана за 8 недель), первая модель классификатор + регрессор, подбор порога, разбор ошибки итоговой модели (`error_breakdown`) и локальная сборка сабмита с проверкой детерминированности.

## 02_eda.ipynb

Анализ данных: общая картина, склады, департаменты, города, категории, лаги и профили по дню недели и месяца, праздники и торговые даты, отдельно категории 1_5 и 1_4. Выводы, которые повлияли на модель, перечислены в `solution.ipynb`, раздел 2. Считается локально примерно за минуту.

## 03_classifier.ipynb

Классификатор отдельно: признаки и настройки, метрики против простого правила, где различает хуже, калибровка, все фолды, сравнение с простыми правилами и потолком, важность признаков, сколько нужно деревьев, польза групп признаков, ошибки. Выводы сохранены с более раннего прогона на Kaggle (1500 деревьев глубины 8): по кривой из этого ноутбука и выбрали 400 деревьев.

## 04_regressor.ipynb

То же для регрессора: метрики на неделях с продажами против обычного количества, по горизонту и размеру пары, калибровка, польза групп признаков, ошибки.

## 05_experiments/

По ноутбуку на идею. Устроены одинаково: `VARIANTS` с вариантами, база считается в том же запуске (обучение на GPU от запуска к запуску плавает примерно на 0.0006), правило отбора как в бэктесте, таблица всех вариантов сохраняется в `results/experiments/grid_<имя>.csv`. На Kaggle такой ноутбук идёт около 15 минут, несколько можно запускать параллельно.

| Ноутбук | Идея | Итог |
|---|---|---|
| `05_experiment` | второй CatBoost с другим сидом | взяли, это версия v5 |
| `05_scale` | множитель количества до округления, порог парой по горизонту | взяли порог 0.55 / 0.5 |
| `05_restock` | признаки появления продажи (пополнение остатка) | не взяли, в пределах шума |
| `05_lgbm` | LightGBM третьим участником ансамбля | взяли |
| `05_lgbm2` | настройка LightGBM | не взяли, выигрыш меньше 0.001 |
| `05_whcat` | категория на складе, веса участников ансамбля | не взяли |
| `05_season` | сезонный вес строк обучения | не взяли |
| `05_disp` | целое и порог по разбросу продаж самой пары | не взяли |
| `05_combo` | сочетания лучших идей | финальный конфиг: v5 + LightGBM, порог 0.55 / 0.5 |
| `05_intmap` | соответствие прогноз -> целое, выученное по фактам | не взяли: на `recent` завышает объём |

Числа и причины по каждой идее лежат в `results/ideas.csv` и в `solution.ipynb`, раздел 6.

## 06_final.ipynb

Финальное обучение на Kaggle: модели по `src/final.py` учатся на всей истории тем же `Forecaster`, что работает в сервисе, сохраняются в `model/`, сабмит считается из сохранённых моделей. Там же проверка, что прогноз по последним 180 дням совпадает с прогнозом по всей истории. Прогон делали ещё с выученным соответствием; после отказа от него модели остались те же, а `model/config.json` и сабмит пересчитаны локально.
